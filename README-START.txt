AI 运营管理平台 · 演示版 v3.9 —— 启动说明

一、怎么起（三选一）
1) Windows：双击 start.bat
   - 会自动找 python3 / python / py，并且确认它真能用才调用；
   - 电脑上没装 Python 也没关系，脚本会自动改用 Windows 自带的 PowerShell 服务（start.ps1），不需要安装任何东西。
2) Mac / Linux：在本目录执行  ./start.sh   （需要 python3）
3) 通用：      python server/server.py
起好后会自动打开浏览器，屏幕上会打印三行：
    UI        http://127.0.0.1:8090/
    Data API  http://127.0.0.1:8090/api/health
    Database  server/data/aiops.db
端口 8090 被占用时会自动换 8091、8092……按屏幕打印的那个数访问。
注意：这一版必须通过上面的方式启动（页面 + 数据服务一起起）。
只用静态方式打开 dist 会导致界面右上角显示「数据服务未连接 · 本次不保存」。

二、双击 start.bat 窗口一闪而过怎么办
在本目录的地址栏输入 cmd 回车，然后执行：
    powershell -ExecutionPolicy Bypass -File start.ps1
这条不依赖 Python，基本都能起。
（另一种情况是电脑把 python 指向了微软商店的占位程序，脚本已做了识别，会自动跳到 PowerShell。）

四、演示账号与演示口令（登录由数据服务校验）
  登录名 / 演示口令（登录页选中账号会自动填好）：
    admin  / admin123   平台管理员（全部权限，可改权限矩阵）
    ops    / ops123     运营值班（提交 / 执行 / 回滚 / 导出，不能改权限矩阵）
    dev    / dev123     业务开发者（提交申请，不能审批）
    user   / user123    业务用户（只看应用广场与个人用量，写什么都被拒）
  口令在库里是 PBKDF2-HMAC-SHA256 + 每账号随机盐，接口不返回口令字段；会话 8 小时（HttpOnly Cookie，
  每次访问滑动续期）；同一账号 5 分钟内连错 5 次暂时拒绝登录，成功与失败都记 login_log。
  现场演示权限差异就切账号：业务用户改权限矩阵 / 重置演示数据会被服务端直接拒（403），
  界面上显示数据服务给的原因，/api/audit 里能看到 denied_put。
  演示口令是弱口令，交付前必须全部替换。v3.1 起演示口令在服务端的弱口令表里，
  所以【第一次登录会先要求换口令】：不换口令只能改口令，任何写操作返回 403（页面直接显示原因）。
  换口令位置：登录页提示框，或左侧菜单「账号与安全」。策略：≥8 位、字母+数字、非常见弱口令、
  不等于账号、不复用当前口令与最近 3 次、有效期 90 天；管理员可在「账号与安全」设临时口令或停用账号
  （停用 = 登录被拒 + 该账号会话全部撤销）。接统一身份认证（SSO / 零信任 / LDAP）走配置中心开关，不改代码。

五之四、v3.9 新增：连不通会主动告警（之前只是留痕）
  监控目标或采集源连续取数失败到达阈值（默认连续 2 轮）就告警，网络断 / 对方重启 / 地址填错都算：
  事件台账多一条（连续 3 轮以上记「紧急」，否则「重要」）、通知中心多一条（含最近一次错误，并说明断连期间指标不再更新）、
  兜底工单多一张（状态「待接管」，按派单映射派给「资源异常」对应的值班岗位，默认「算力资源值班」），审计写 monitor_alert。
  只告一次不刷屏：后面几轮继续留痕但不再发通知；重新采到 → 发恢复通知、兜底工单自动关闭、状态回「正常」（审计 monitor_recover）。
  可调（配置中心 · 资源接入与采集 面板右下角）：「断连要告警」开关、以及「连续几轮采不到就告警」（1 / 2 / 3 / 5，默认 2）。
  关掉开关时仍然留痕（取数失败状态 + 连续轮数），只是不发通知。监控页与配置中心都能看到「已告警（连续 N 轮）」。
  没人接管会被追：兜底工单挂超过 15 分钟（可配 0 / 10 / 15 / 30 / 60，0 为不自动升级）无人接管 → 工单变「已升级」、改派带班角色（默认「值班长」）、
  再发一条「紧急」通知；面板里也有「巡检兜底工单」按钮可以手动追一遍并看待接管清单。
  恢复类通知不用人点：取数恢复时系统自动记为已处置（handled_by=系统自动闭环）；要人处置的只有「取数中断」和「无人接管，已升级」两类。面板上有「重新拉取」按钮。
  通知中心顶部新增「真实告警通知」面板：监控断连 / 兜底升级 / 恢复通知都在这里，未处置会一直挂着，点「我处置了」写一句说明即记录到人（要「运营分析」操作权）。
  闭环落到人：监控页下方「断连兜底工单」表里可以点「我接管」（记录谁、几点）与「处置完毕 · 关闭」（必须写原因；目标还没通时会提醒你「关闭只是处置登记」）。
  错误文本能帮你分清找谁：Connection refused = 端口没人监听；timed out（端口能连上）= 服务不响应；401 = 服务活着但密钥不对。
  值班第一眼看到的地方读真实告警：顶栏铃铛显示「真实告警待处置 N 条」并把最近一条直接列在旁边（等级 + 标题 + 时间），
  侧栏「通知中心」角标同口径，每 20 秒跟库里的状态对齐；演示推导的通知单独放在下面一个面板并标明不是真实采集。
  修了一个真 bug（界面点了没反应的原因）：前端 API_BASE 已经是 /api，几个新按钮把路径写成 /api/monitor/… → 打到 /api/api/… → 404，
  既不报错也不留审计。已改对；未知接口现在也落审计（unknown_api，报错直接提示「多写了一层 /api」）。
  两个体检脚本：tools/check_api_paths.py（前端调用有没有重复 /api 前缀）、tools/audit_ui_api.py（服务端接口清单 × 界面调用清单 × 失败静默点）。
  诚实边界：时延 / 错误率 / 排队深度这类「指标阈值」告警目前还写在页面常量里（900 毫秒 / 2.4% / 40），下一步搬进配置项。

五之四之补、v3.9.9 / v3.9.10 界面观感：五套配色与反差整改
  顶栏右侧「配色」切换五套：深空蓝（默认）/ 墨青 / 纸白 / 公文灰 / 高对比。选择记在数据服务（状态键 dsh-demo-ui-v1），换台电脑登录还是这套。
  换肤靠颜色令牌：样式表里的硬编码颜色全部改成 --bg / --panel-grad / --line / --text-faint 这类令牌，再用 [data-theme=…] 覆盖。墨青、纸白、公文灰、高对比把辉光、渐变、投影关掉，界面就"素"了。
  图表跟皮肤一起换：图表组件在渲染前覆盖文字色、坐标轴与网格色、提示框底色与系列配色。
  反差是按 WCAG 2.1 量出来的，不是凭感觉：tools/check_contrast.py 逐套算正文 / 次要文字 / 微弱说明 / 面板标题 / 徽章对背景的比值，另算面板与页面的明度分隔。现在正文 13.4–18.4:1、次要 7.3–13.4:1、微弱说明 5.4–8.4:1（上一版只有 3.7–4.1:1，低于 4.5 的可读底线，这就是"看着糊"的直接原因）。改完配色跑这个脚本，不达标直接报错退出。

五之三、v3.8 新增：资源接入在系统里配（加资源不改代码、不改文件）
  入口：运营分析 · 配置中心 → 面板「资源接入与采集」（要「权限矩阵」操作权）。
  配一条采集源就行：资源类型（推理服务 / 算力卡 / 网关 / 路由 / 应用 / 部署台账）+ 显示名 + 地址 +
  取数口径（JSON 指标 / Prometheus 文本 / OpenAI 兼容）+ 采集间隔 + 取密钥的环境变量名；
  特殊指标名（DCGM / NPU Exporter 的指标名、每副本卡数之类）写在「附加配置」的 JSON 里。
  配置存 data_sources，采集结果入 collect_payloads，页面主表格读接口 /api/collect；采集线程在数据服务里自动按间隔跑。
  密钥红线：配置里写明文 api_key / token / password 会被直接拒绝，只允许 "env:环境变量名" 引用（值由启动环境给）。
  可选开关「接入要先审批」（配置项 data-source-approval）：打开后新增或变更先生成 resource_onboard 工单，
  源显示「待审批」不采集；审批台通过后自动生效并采一轮，驳回则不生效；两种模式都写审计。
  取数失败会留在源上（状态「取数失败」+ 错误文本），不会静默变空页。data_sources / collect_payloads 不受「重置演示数据」影响。
  老配置迁移：面板里「从采集脚本配置文件导入」把 collector/config.json 一次性搬进系统，搬完文件不再被读。
  关掉内置采集线程：启动前 set AIOPS_COLLECT=0。npU-smi 直采仍只在采集脚本里（要在本机执行命令，不由界面触发）。

五之二、v3.7 新增：平台内置监控探针（真实采样入数据库）
  数据服务自带一个只读探针线程：按每个目标自己设定的间隔去拉外部推理服务的 GET /metrics 与 /health，
  把带时间的采样写进 metric_samples、把真实卡指标写进 gpu_cards。不向被监控的服务写任何东西。
  界面入口：模型中心 · 推理服务监控 页底部「平台内置监控探针」（挂目标 / 立即采一轮 / 启停 / 趋势曲线 / 采样台账）；
            算力中心 · 算力卡监控 页底部「实连 GPU」（这张表是真实拉到的，与 64 张卡的演示推导口径分开显示）。
  密钥：目标配置里只存「环境变量名」，密钥本身要在启动数据服务前 export 好（例 MODEL_SVC_API_KEY），库与前端都不存密钥。
  取数口径（每个目标单独选）：JSON 指标（对方 /metrics 返回 JSON）/ Prometheus 文本（llama-server --metrics、vLLM、GPU Exporter）/
  只有 OpenAI 兼容接口（只给 /health 与 /v1/models：这时只有可用性、模型清单和「主动探测」测出的时延吞吐，卡指标标「对方未开放」）。
  主动探测默认关闭；勾上才会每轮发一个 16 词元的小请求。
  关探针：启动前 set AIOPS_MONITOR=0（手机 / 单机演示不需要外网时可以关）。
  采样保留默认 24 小时、上限 20000 行；metric_samples / gpu_cards / monitor_targets 不受「重置演示数据」影响。
  连不通也留痕：那一轮状态写「取数失败」并留审计 monitor_probe_failed，台账里能看到从什么时候开始采不到。
  自查接口：/api/monitor（目标与最近一轮）、/api/samples（采样台账）、/api/gpu_cards（实连卡）。

五、这一版（v3.0）的登录、权限与查询变化
  - 登录改由数据服务校验（不再是免密切换）：POST /api/login → HttpOnly Cookie 会话；
    写状态键要对应权限点，批量写入 / 重置演示数据要「资源调配」权，查审计要「审计日志」查看权，
    导出要「报表导出」权；越权返回 403 并写一条 denied_put 审计。前端把菜单灰掉只是体验。
  - 新增页面：运营分析 · 台账与审计（查库） /ops/records —— 工单台账 / 运行事件 / 写入审计 / 数据库概览，
    四个页签都是服务端过滤与分页查询（/api/orders、/api/events、/api/audit、/api/tables），
    面板上直接显示本次请求的 URL，导出 CSV 由服务端生成（带 UTF-8 BOM）。
  - 运行事件长期留存：界面只留最近 80 条，库里按「时间 + 内容」去重累积，翻页能看到更早的事件。
  - 业务状态全部落数据库：server\data\aiops.db（SQLite）。浏览器不再使用本地存储，
    关浏览器、换浏览器、换电脑看到的都是同一份数据（把 db 文件拷走即可带走）。
  - 界面右上角有数据状态牌：数据已存库 / 写入中 N / 写入失败·重试中 / 数据服务未连接·本次不保存。
  - 后台自查：http://127.0.0.1:端口/api/health（行数汇总）、/api/orders?status=待审批、
    /api/audit?limit=50、/api/entities?kind=connector、/api/export（全量导出）。
  - 「恢复初始演示数据」= 清空业务表再写回初始值（POST /api/reset）。要彻底出厂：停服务后删
    server\data\aiops.db（含 -wal / -shm）再启动。

六、提醒
  - 演示数据每 4 秒采样刷新，是运行态演示；数字之间是真实推导关系，可以现场改副本、改权重、做处置，看调用量 / Token / 成本同步变化。
  - 所有数字、人员、事件、外部系统均为虚拟模拟；真实接入需接口文档与联调环境。
  - 演示前建议在工作台点「恢复初始演示数据」，保证现场数字可复现。

    卡级告警（利用率超阈 / 温度超阈 / HBM 超阈 / 掉卡隔离 / ECC 偏高）可就地送例外监控、卡表 vs 池化分配对照。
  模型中心 · 推理服务监控 /model/monitor
    服务级副本与就绪、占用卡位、QPS、吞吐、首包 TTFT、P99、队列深度、KV 命中、HBM 占用、错误率、重启；
    触线服务一键提副本扩容工单，准入被拒时原样显示理由。
  模型中心 · LiteLLM 网关仪表 /model/litellm
    按 key 看配额与当前占用（个人密钥 120 RPM / 平台代理 400 RPM）、当日请求 / Token / 成本 / 错误 / 回退；
    渠道与路由权重分布；网关侧 key 与平台凭证台账双向对账；限流与吊销都以工单提交。
  模型中心 · 模型部署与发布 /model/deploy
    平台发单 → 准入校验 → 审批 → 下发容器平台 → 执行回执到位才生效（副本与卡位才变）→ 可回滚；
    未回执期间不占卡位；回执超 30 分钟在看板上标「回执超时」；失败回执进台账且不动资源。
  模型中心 · 模型安全检测流程 /model/safety-flow
    输入 → 前置检测 → 路由与推理 → 后置检测 → 判定与动作 → 审计留痕，五步逐个显示请求 / 响应 / 判定 / 耗时；
    判定接处置引擎生成工单（切调用不切资源）；面板写明接真实检测引擎的三个接口契约与待定口径。
  应用中心 · Dify / RAGFlow 纳管（第一期）/app/dify
    应用与数据集清单、发布 / 草稿 / 已下线状态、绑定模型与归口；与平台归口目录做一致性核查；
    未登记的一键登记进接管册并联动例外监控。第一期只读，日志与配额下发属第二期。
  运营分析 · 申请与审批台 /ops/apply
    普通用户申请 Key（用途 / RPM / TPM / 期限 / 理由）与申请训练算例（1–8 卡 / 1–72 小时 / 框架 / 数据密级）；
    管理员审批或驳回（驳回须写理由）；训练卡位归还走工单留痕并即时反映到池利用率。

八、v2.1 相对 v2.0 的增量（口径落定后的两处改动）
  1) 昇腾卡指标双取法 + 自动兜底：Prometheus（NPU Exporter）优先，查询无数据或连不通时自动改跑节点侧 npu-smi；
     日志与 manifest.json 写明这一轮实际用的是哪条路，两条都空才记「取数失败」。
  2) 部署执行回执自动回填：模型部署页新增「容器平台执行回执（采集层取回）」一栏 —— 采集脚本每轮把容器平台回执取回来列在页面上，
     点「按这条回执生效」才登记生效（成功 → 副本与卡位变化；失败 → 工单记「已驳回 · 执行失败」且不动资源）；工单号对不上的回执直接标「工单不存在」。
  3) 外部接入配置中心新增两条指标源（昇腾 NPU Exporter + npu-smi 兜底、MindIE 指标源），全站接入配置 28 条；
     容器平台部署通道状态由「待商定」改为「已定」（回执接口已确认可提供，剩工单号回传规则与超时口径）。

九、接公司内网真实数据（可选，演示包本身不联外网）
  1) 先把字段结构跑通：      python3 collector/collect.py --selftest --out dist/data
     刷新页面，各页顶部标记会从「平台推导」变成「采集层」。
  2) 再接真实接口：          cp collector/config.example.json collector/config.json
     填 MindIE 指标地址、LiteLLM 地址与只读 key、Dify 只读账号、RAGFlow Token、昇腾 Exporter（Prometheus）地址与查询名、容器平台回执接口地址与 token；
     密钥一律写 env:变量名，不要写进文件。然后：
                            python3 collector/collect.py --config collector/config.json --loop 30
  2.5) 只想要昇腾数据、Prometheus 一时接不上：把 cards.mode 改成 "npu-smi"（或保持 "prometheus"，脚本会自动兜底跑 npu-smi）。
  3) 口径说明（重要）：
     - 采集脚本只读，绝不向任何外部系统写数据；阻断 / 限流 / 部署 / 回收一律是平台工单，由运维或容器平台执行并回执。
     - 某一路取不到，页面上写「取数失败 + 原因」，整体模式显示「部分采集」，该块回落平台推导 —— 不猜数、不补数。
     - manifest.json 生成时间超过 15 分钟，页面自动视为过期并回落平台推导。
  4) 需要客户方 / 厂商确认的接口与字段，全部列在 docs\intranet-api-checklist.md。

十、此前 v1.10 已做的例外处置闭环（仍可用）
  算力中心 · 例外监控与阻断 /compute/exceptions：
  - 整改闭环台账：处置后自动开整改单（责任人 / 内线 / 接单时限 / 整改期限 / 进展 / 复核通过或退回 / 关闭）；复核未通过不允许恢复接入
  - 派单与值班：按例外类型派给当班角色，超时未接单自动升级值班长，超整改期限台账与事件流同时标出
  - 部分阻断：阻断范围可选「全通道 / 采集项 / 时段 / 来源 IP」，部分阻断时接入通道仍启用、只切该来源；写法不合规会被准入拒绝
  - 检测数据源：流量探针 / 设备 Syslog·SNMP / CMDB 台账比对三条配置可开关，接入即多出旁路检出（喂数为模拟数据）
  - 未纳管调用来源（台账有调用量但不在纳管目录）已升级为正式例外，可就地吊销或限流其凭证
