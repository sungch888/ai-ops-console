# 算力池借还与换池设计 v0.1（规则、流程、前提要素明示）

> 口径：推理/训练"分开"= **逻辑隔离 + 可回收配额**，不是两套物理隔绝的集群。
> 跨池调度只有一个裁判：**本单元的余量台账**；两个平台不得各记各的账。
> 时间档纪律：秒级留在池内（分时/休眠唤醒），**分钟级=政策化借还，小时级=换池工单**。跨池不做秒级承诺。

## 1. 前提要素（缺一不可，缺项时行为明确）

| # | 前提 | 不满足时的行为 |
|---|------|----------------|
| P1 | **台账真值唯一**：两连接器 `inventory/capacity` 回灌台账，每卡有 `pool_type / reclaimable / grace_sec / checkpoint_every / reserved_for` | 禁止一切自动借还，只允许人工工单 |
| P2 | **任务三属性入库必填**：可回收(是/否)、宽限期(≥300s 建议)、checkpoint 频率 | 视为**不可抢**，永不出借（不是拒绝，是降级） |
| P3 | **借还政策先获批**：时段、芯片型号、上限/下限、冷却、单次借用量，版本化对象（AP 模式） | 未获批策略不得触发任何自动动作（同 AP-02 演练标） |
| P4 | **训练侧能证明 checkpoint**：最近一次保存 ≤ 声明频率，任务才可被预约 | 该卡不入出借清单，跳过并留痕 |
| P5 | **推理侧能排空迁移**：副本先 drain、目标池有余量或预约能在宽限期内到位 | 扩容等待排队，不得硬抢 |
| P6 | **借=预订**：先挂预约再回收；唯一例外是 P0 故障紧急借用，事后 24h 补审 | 直接抢占视为违规操作，审计拦下 |
| P7 | **换池两侧通道可用**：GPUWorks 节点下线/接入 + CubeStudio 入集群打 label，缺一改人工 | 换池只走人工核对，不走自动 |
| P8 | **容量口径一致**：同一张卡任何时刻只在一本账上；借出即从训练侧账本划出 | 校验不平 → 冻结该池自动借还并上报 |

## 2. 逻辑规则（R1–R10，写进策略与代码，不靠临时拍板）

1. **R1 抢占优先级（固定）**：在线推理 SLA ＞ 归还窗口内的预约执行 ＞ 可回收训练 ＞ 不可抢训练 ＞ 空闲。
2. **R2 只借"可回收额度"**：出借量 ≤ 该额度未占用部分；训练"单申请 ≤8 卡"的上限同样适用于借用量。
3. **R3 借=预订**：预约单写明目标任务、归还期限、宽限期；被约任务收到通知后在 checkpoint 点**主动挂起**；宽限期满未挂起 → 升级人工，不硬杀。
4. **R4 到期必还**：归还期限到且推理峰已过 → 自动归还；要延期必须另起新预约，不自动续借。
5. **R5 扩缩容联动**：阈值触发扩容且本池余量不足 → 只有台账存在可回收预约才可执行，工单须写余量数与预约号，否则转人工审批。
6. **R6 换池=高危长时操作**：变更单 + 双人复核 + 变更窗口，**禁用紧急通道**；换池前节点必须排空且无在途预约。
7. **R7 自动动作只在获批边界内**：时段/上限/下限/冷却/芯片型号任一越界 → 拦下转人工。
8. **R8 台账校验**：每次借还/换池后按连接器实读对账；不一致 → 该池自动借还冻结并通知责任人。
9. **R9 时间档不越界**：借还 SLA 明示分钟级；页面与文案不得出现"秒级跨池调度"承诺。
10. **R10 失败如实**：checkpoint 失败 / drain 超时 / 入池失败 → 分段部分成功语义，台账不划转，生成兜底待办，可接管。

## 3. 业务流程（四流程，含门禁锚点与失败分支）

### F1 夜间自动释放（政策驱动，自动）
22:30 策略触发 → 扫训练池「可回收额度」任务 → 发挂起通知（宽限 10min）→ checkpoint 确认 →
CubeStudio `drain`（lend 分段）→ 卡划入推理池（GPUWorks 登记/cordon→uncordon）→ 台账回写 + 通知值班。
失败分支：无有效 checkpoint → 该卡跳过留痕；drain 超时 → R10。

### F2 预约借用（阈值驱动，政策内自动 / 越界转人工）
监控 P99/队列越限 → 建「弹性借还」运营任务单（附余量数 + 策略版本 + 预约号）→ 边界内自动执行：
预约 → 挂起&checkpoint → 排空 → 入推理池 → 台账回写；扩容本体走 OC-F-01 既有路径。
到期按 F4 归还；**全程分段状态以两侧执行体回报为准**，人工不得先判过。

### F3 换池（人工驱动，全门禁）
申请单写明换池原因与预计时长 → 变更单审批 + **双人复核** + 预约窗口 →
原池排空 + 在途预约核对 → 原平台下线 → 新平台注册 + 打标签 → 台账 `pool_type` 变更 → 两侧容量回读校验。
禁用紧急通道（R6）；每段独立成败，失败保持事件在途。

### F4 归还（期限到，自动）
推理侧副本排空 → GPUWorks 下线 → CubeStudio 入池 → 训练任务载 checkpoint 恢复 →
台账校验 + 通知训练责任方。归还失败 = 严重事件，推理侧占用继续计费留痕。
