# AI 算力与模型运营平台 · 逻辑架构（一页纸 · 汇报用）

> 用途：向领导汇报系统的逻辑架构与运行边界。不谈代码与技术选型，只谈分层、闭环和责任边界。
> 口径来源：当前演示版 v3.10（41 个功能入口 / 26 张业务表 / 18 个权限点 / 16 类工单 / 6 类例外 / 28 项外部接入配置 / 11 个可改口径）。

## 一句话定位

**面向示例单位信息网的「AI 算力与模型运营」管理平台**：把算力资源、模型服务、智能体应用三类资产统一纳管，
用「工单 → 审批 → 执行 → 回执 → 验证 → 审计」把日常运营动作闭环，并把异常检测与处置也闭环；
平台不擅自改动外部系统，需要外部执行的动作一律走工单与回执。

## 逻辑五层

| 层 | 管什么 | 现在有多少 |
|---|---|---|
| 1 使用者与角色 | 管理员 / 运营值班 / 模型技术 / 业务用户四类角色，按权限点决定能看什么、能改什么；权限在数据服务侧判定，前端改不动 | 4 类角色 · 18 个权限点 |
| 2 业务功能区 | 总览、算力中心、模型中心、应用中心、运营分析五大区 | 5 大区 · 41 个功能入口 |
| 3 运营闭环引擎 | 资源池扩缩、副本与路由权重、凭证发放与吊销、配额调整、接入阻断与恢复、模型回滚与下线、部署与训练排队等工单，走审批、变更窗口、执行、外部回执、效果验证 | 16 类工单 · 8 种状态 |
| 4 监测与处置 | 六类例外检测（旁路接入、旁路调用、接管缺口、资源异常、配额越界、目录不一致）、四级接管深度、告警规则、整改单派单与复核 | 6 类例外 · 4 级接管深度 · 8 条内置告警规则 |
| 5 数据与外部对接 | 工单、审批、事件、通知、指令、兜底工单、排班派单、凭证、指标采样、审计等业务表；外部系统按「接入配置」接入，改配置不改程序 | 26 张业务表 · 28 项接入配置 · 11 个可改口径 |

## 三条闭环主线（汇报就讲这三条）

1. **资源调配闭环**：申请 → 审批（可驳回并留理由）→ 变更窗口排队 → 执行 → 外部执行回执回填 → 效果验证 → 台账与审计。
   需要外部动手的（模型部署、扩缩容）平台只发单，回执到位才登记生效；紧急处置类不受变更窗口限制，可即时阻断。
2. **例外处置闭环**：检出例外 → 切断「例外接入来源」（切通道 / 凭证 / 调用入口 / 目录入口，资源本身不停不回收）→
   自动开整改单派给当班角色 → 接单 → 整改 → 复核通过 → 才允许提交恢复接入。止损与整改分开，谁整改、谁复核都有记录。
3. **监控告警闭环**：只读探活连续取不到数 → 事件 + 通知 + 兜底工单派值班岗位 → 挂满时限无人接管自动升级带班 →
   人处置或取数恢复后自动闭环。**同一原因重复报警只留最新一条要处置，之前的自动完成处置**，值班不必逐条点。

## 数据口径（领导常问的两点）

- **谁写谁读**：业务状态写在数据服务的数据库里，浏览器不存业务数据；台账、审计、导出直接查库（服务端分页与过滤），
  写失败会在界面上明确显示，不假装已保存。
- **真实数据与演示数据分得开**：真实采集来自平台自己的只读探针（推理服务指标、算力卡、数据源）；
  演示推导的部分在页面上明确标注「演示推导 · 不是真实采集」，两者不混用，取数中断时显示缺口而不是拿旧读数冒充实时。

## 已经跑通 vs 接口留位（谈判口径）

| 平台内已闭环，现在就能用 | 接口与位置已留，待客户方或厂商给条件 |
|---|---|
| 资源调配与审批、驳回留理由 | 统一身份认证：CAS / OIDC / LDAP 待客户方定协议与签发方 |
| 例外检出与切断、处置记录到人 | 外部审批系统对接：回调位已留，可切换外部审批来源 |
| 整改单派单闭环（接单 / 整改 / 复核 / 恢复接入） | 处置指令真实下发：预检、下发、确认、超时回滚已闭环，实际执行接口待厂商开放 |
| 监控告警与兜底接管（同因归并、超时升级） | 模型安全检测引擎：流程与展示已通，检测引擎待接 |
| 台账、审计、报表与 CSV 导出 | 第二期对接：调用日志、配额下发、知识库条目、用户与权限映射待厂商开放 |
| 权限矩阵、口令策略与登录留痕 | 短信 / 值班电话等通知通道：开关已留，需客户方给通道与凭证 |

## 责任边界（一句话讲清谁负责什么）

- **平台负责**：看得见（统一台账与指标）、管得住（审批与变更窗口）、追得到（审计与归口）、兜得了（外部不可用时的接管与降级）。
- **客户方负责**：认证源与协议、通知通道与凭证、外部审批与执行系统的接口、归口部门与值班岗位指定。
- **厂商负责**：真实执行（扩缩容、部署、阻断落地）与执行回执；回执不到位，平台记「待回执」并开兜底工单，不静默当作已完成。

## 给领导的三句话

1. **一套工单口径管所有运营动作**：谁申请、谁批、什么时候执行、结果是否回填、效果有没有验证，全程可查、可追责。
2. **异常不是弹提示，而是有处置链**：界面上的红黄告警点进去就是能动手的那一条；同因重复报警只留最新一条要处置，旧的自动闭环。
3. **平台不擅自改外部系统**：需要外部动手的动作一律走工单 + 回执 + 兜底接管，超时自动升级带班，边界清楚、留痕完整。

## 三分钟口头汇报脚本

- 30 秒：定位——三类资产统一纳管，运营动作和异常处置都闭环，平台不擅自改外部系统。
- 60 秒：五层结构——角色权限 / 五大功能区 / 工单闭环 / 监测处置 / 数据与对接，各层数量报一遍。
- 60 秒：三条闭环各讲一句，重点讲「切断的是接入来源，资源不停」和「同因重复只处置最新一条」。
- 30 秒：边界——已闭环 6 项、待客户方或厂商 6 项，需要客户方定的三件事（认证源、通知通道、归口与值班）。
