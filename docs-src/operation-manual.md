## 0. 三句话先讲清楚这套系统怎么用

1. **平台只管运行态**：纳管、监控、审批、处置、审计、报表。智能体编排、Prompt 调试、向量化、插件安装是各子系统自己的事，平台不做。
2. **危险动作都不是平台直接干的**：暂停、限流、隔离、吊销、扩容、部署，平台做的是「准入校验 + 审批 + 发单 + 验收回执 + 留痕」。容器侧执行由容器平台/运维做，设备侧动作由设备与机房做。
3. **数据分两种来源**，页面上都会写明：`采集层`（从外部系统真取回来了）或 `平台推导`（按资源账本与调用账本推导）。取不到就标「取数失败」，**不猜数、不补数**。

## 1. 打开系统

### 1.1 本地启动（三选一）

| 环境 | 操作 |
|---|---|
| Windows | 双击 `start.bat`。会自动找 Python；**没装 Python 会自动改用系统自带 PowerShell**（`start.ps1`），不需要安装任何东西 |
| Mac / Linux | 在包目录执行 `./start.sh`（需要 python3） |
| 通用 | 在包目录执行 `python server/server.py`（同时启动页面与数据服务） |

启动后浏览器自动打开，屏幕打印三行：`UI http://127.0.0.1:8090/`、`Data API http://127.0.0.1:8090/api/health`、`Database server/data/aiops.db`。
8090 被占用会自动换 8091、8092……**按屏幕打印的那个地址访问**。

`start.bat` 窗口一闪而过的处理：在包目录地址栏输入 `cmd` 回车，执行
`powershell -ExecutionPolicy Bypass -File start.ps1`

### 1.2 登录（演示口令，四个演示账号）

| 账号 | 角色 | 登录名 / 演示口令 | 能做什么 | 不能做什么 |
|---|---|---|---|---|
| **管理员 A（信息化管理部）** | 平台管理员 | `admin` / `admin123` | 全部权限；可审批与执行；可编辑权限矩阵 | — |
| **运营 B（运营服务团队）** | 运营值班 | `ops` / `ops123` | 提交、执行、回滚、导出、处置 | 不能改权限矩阵 |
| **开发者 C（示例业务一部）** | 业务开发者 | `dev` / `dev123` | 看本单位业务线、提交申请、看审计 | **不能审批** |
| **用户 D（示范市02单位基层所队）** | 业务用户 | `user` / `user123` | 应用广场、个人模型中心、凭证申请、模板库 | 看不到审计、工单审批；敏感级模板引用被禁用 |

登录页选中账号会自动填好登录名与演示口令（也可手输），口令由**数据服务校验**：口令在库里是 PBKDF2-HMAC-SHA256 + 每账号随机盐，接口不返回口令字段；会话 8 小时（每次访问滑动续期）；同一账号 5 分钟内连错 5 次暂时拒绝登录，登录成败都记 `login_log`。**演示权限差异就靠切账号**（1 分钟能讲完）。
演示版已有服务端会话与权限判定（越权写入直接 403）；真实身份接入方式（统一认证 / 零信任 / 双域账号映射）属待商定项，页面上只给位置与字段。

### 1.2.1 首次登录会被要求换口令（v3.1 起）

四个演示口令（`admin123` 等）都在服务端的常见弱口令表里，所以**第一次登录会先弹出「换口令」框**，不换口令只能改口令、不能做任何写操作（服务端返回 403，页面上直接显示原因）。这是刻意做的：演示口令不能带进正式环境。

- 换口令的位置：登录页的提示框，或登录后左侧菜单「账号与安全」。
- 服务端口令策略：至少 8 位、必须同时含字母和数字、不接受常见弱口令、不能与账号相同、不能复用当前口令或最近 3 次用过的口令、有效期 90 天（超期登录即要求换）。
- 换完口令当前会话立刻失效，需要重新登录；旧口令永久不能再登录（`password_history`）。
- 管理员可以在「账号与安全」里给某个演示账号设临时口令（置为「下次登录必须改」），也可以直接停用账号（该账号会话全部撤销、登录被拒）。

同一账号 5 分钟内连错 5 次会暂时拒绝登录（429）；登录成功与失败都进 `login_log`。
写操作还要带 `X-CSRF-Token`：这个令牌由服务端在登录时下发、前端只存内存，浏览器控制台里看不到也存不下。

### 1.3 界面结构

- **左侧菜单**：按「总览与接管 → 算力中心 → 模型中心 → 应用中心 → 运营分析」分组，共 34 项。**菜单项按权限显示**，账号权限不够的页面直接不出现。
- **页面标题行**：页面名 + 状态徽标（待审批 / 待回执 / 取数来源 / 例外数等）。
- **每个面板右上角的 `extra`**：实时计数（共几条、待处理几条）。
- **左下角常驻**：「演示版本 v3.0（选型交流 · 内网可接真实数据）」+「业务状态存数据服务（SQLite）· 登录与权限在服务端判定」—— 讲的时候不用回避。
- **右上角数据状态牌**：`数据已存库` / `写入中 N` / `写入失败 · 重试中` / `数据服务未连接 · 本次不保存`。演示前先看这一格，绿色才开场。
- **投屏页** `/briefing`：暗色大屏汇报页，可翻页，右上角可切亮/暗。

### 1.4 恢复初始演示数据（重要）

- 位置：`/ops/workflow`（资源调配工作台）→「恢复初始演示数据」/「重置演示数据」。
- **每个场景跑之前先按一次**，保证结果可复现、数字对得上。
- 你所有操作（工单、例外、配置、权限矩阵、通知）都写进**数据服务的数据库**（`server/data/aiops.db`），浏览器只保留一份内存副本。按「重置」= 调 `POST /api/reset`：清空全部业务表再写回初始演示数据。
- 想彻底回到出厂状态：关掉服务，删掉 `server/data/aiops.db`（连带 `-wal` / `-shm`）再启动即可；浏览器缓存不影响数据。

### 1.5 数据是怎么动的

- 运行态采样：调用量 / Token / 成本 / 池利用率随时间推进，工作台可「采样一次」或开自动采样。
- 你改一个动作（副本、权重、处置、扩容、回滚），相关数字**同步变化**，可以现场来回做。
- 采集层数据：由采集脚本每轮写入，页面每 30 秒拉一次；超过 15 分钟视为过期自动回落平台推导。
- 写入路径：你每一次改动先进内存（界面立即反映）→ 排队的写请求自动 `PUT /api/state/<键>` 落库；成功后右上角显示「数据已存库」。

### 1.6 数据存在哪里（v2.2 起）

> v3.0 起还有一件事：登录与权限也在数据服务。前端把菜单灰掉只是体验，真正的拦截在 `/api`（越权返回 403）。

- **权威数据在数据库**：`server/data/aiops.db`（SQLite，WAL）。同一目录换机器跑，把这份文件一起带走即可。
- **浏览器本地不存数据**：不用 localStorage / sessionStorage / IndexedDB；关掉浏览器、换电脑、换浏览器都能看到同一份状态。
- **库里存什么**：完整状态快照表 `kv_store`（19 个状态键）+ 投影出来的可查询表 `orders`（工单）、`order_trace`（处置轨迹）、`events`（运行事件）、`notifications`（通知）、`accounts` / `role_permissions`（账号与权限矩阵）、`entities`（凭证、渠道、接入配置、接管范围、模板、策略、报表、告警规则等）、`settings`（开关与配置）、`audit_log`（每一次写入的留痕）。
- **查数据不用开界面**：`http://127.0.0.1:8090/api/health`（自检与行数）、`/api/orders?status=待审批`、`/api/audit?limit=50`、`/api/entities?kind=connector`、`/api/export`（全量导出，用于备份与换库迁移）。
- **接口契约与表结构**：`docs/api-contract.md`、`server/schema.sql`；正式版换 PostgreSQL 的做法见 `docs/architecture.md`。

## 2. 权限怎么调（现场 1 分钟演示）

1. 用**管理员 A**登录 → `/app/accounts` → 「角色权限矩阵（可编辑 · 立即生效）」。
2. 把某一格从「可操作」改成「只读」或关掉 → **立刻退出登录换个账号看菜单与按钮变化**（例：关掉某处室的 `gateway` 权限，该账号连 `/model/gateway` 都看不到）。
3. 演示完点「恢复默认矩阵」。
4. 权限维度是 **角色 + 数据密级**：敏感级模板对低密级账号显示但引用按钮禁用。

可用的权限点（18 个，v3.6 起安全处置拆成三档）：运营总览、算力中心、推理网关、凭证与配额、资源调配、应用广场、智能体纳管、知识库纳管、工具生态、安全事件、调用审计、权限矩阵、导出、外部对接、运营分析、审批。

## 3. 逐页操作说明（按左侧菜单顺序）

> 每页给四件事：**用途 → 看什么 → 能做什么（点了会怎样）→ 注意 / 会被拒**。
> 「只读」的页面不会改动任何数据；「可操作」的页面提交的都是一张**工单**，要过准入校验与审批。

### A. 总览与接管范围

#### A1 运营总览 `/`（权限：运营总览）
- **用途**：值班第一屏，看今天整体健康度。
- **看什么**：近 24 小时调用量趋势、在线模型负载分布、各地市调用量排行、今日安全事件动态、核心应用调用 TOP、国产化算力卡概况。
- **能做什么**：只读（点卡片跳到对应中心页）。
- **注意**：卡概况这里显示的是**登记口径 88 卡 / 池化 46 卡**，与卡监控页的物理 64 卡不是同一个口径，差异在卡监控页有对照表。

#### A2 统一接管范围 `/govern`（权限：运营总览）
- **用途**：回答「你们能接管我们哪些东西、接管到什么深度」。
- **看什么**：接管深度阶梯 L1–L4、接管登记册（25 项）、各类别覆盖率、覆盖率明细、与客户方文档的对照。
- **能做什么**：
  - 「新增接管对象登记」：填名称 / 类别 / 卡位 / 归口 / 绑定的接入配置 → 入册（新增资源入册走这里）。
  - 「把已登记对象接到接入配置上」：绑定 / 解绑一条接入配置 → **接管深度实时变**（未绑定 L1；通道启用 L2；接口已定 L3；接口已定 + 回执类前置完成 L4），覆盖率与「可调度总量」同步变。
- **会被拒**：`同名对象已登记，请改名或补充来源区分`；`接入对象名称与责任方不能为空`。
- **注意**：深度不是勾出来的，是由「绑定关系 + 通道启用 + 接口状态 + 前置条件」推出来的，解绑就退回，口径不掺水。

#### A3 投屏汇报首页 `/briefing`（权限：运营总览）
- **用途**：会议室投屏汇报，暗色大字。
- **能做什么**：翻页（现状 → 三中心 → 已实现闭环清单 → 待确认口径）；右上角切亮/暗；「返回平台」回工作台。
- **注意**：这一页没有操作动作，纯讲。

#### A4 部署形态与网络分区 `/network`（权限：运营总览）
- **用途**：对比「一套跨网部署」与「三套各自网内部署」。
- **看什么**：选中某个网络平面后，看该网内的模型与渠道、应用与用量、工具/插件与凭证；下方两种部署形态对比表。
- **能做什么**：切换网络平面（点选）。
- **注意**：选型结论要客户方定，页面只给对比依据。

#### A0 账号与安全 `/account`（任何已登录账号都可进）
- **看什么**：当前账号与角色、口令状态（正常 / 必须更换）、有效会话数、口令策略。
- **能做什么**：
  - 更换自己的口令（当前口令 + 新口令 + 再输一遍）；被拒时直接显示服务端给的原因（太短 / 没有数字 / 常见弱口令 / 与账号相同 / 复用最近用过的口令）。
  - 看自己当前的所有会话（编号、来源 IP、建立与最近活动时间、剩余有效分钟），逐条「撤销」；没有「权限矩阵」查看权的人只能看到并撤销自己的会话。
  - 管理员额外可：给演示账号设临时口令（下次登录必须改）、停用 / 开通账号。
- **会被拒**：改别人的会话、停用账号 —— 没有矩阵权限时 403，页面上原样显示原因。

### B. 算力中心

#### B1 算力资源总览 `/compute/overview`（权限：算力中心）
- **看什么**：节点资源监控、算力卡厂商分布、节点明细、算力事件与自愈、异构算力平台与资源接管范围。
- **能做什么**：只读。
- **注意**：这里的「自愈」是演示事件，不回收卡位。

#### B2 资源池与调度 `/compute/schedule`（权限：算力中心；审批要「审批」权限）
- **用途**：三个池（高保 / 共享 / 灰度）的卡位分配与调度策略。
- **看什么**：扩缩协同队列、调度策略、调度等级划分、节点资源池归属、容量评估与变更约束。
- **能做什么**：对队列里的工单点「通过并执行」或「回滚」。
- **会被拒**：
  - `抢占仅限高保业务（调度等级须为「高保」），共享 / 灰度业务须走常规扩容`
  - `扩容卡位必须为正整数` / `抢占卡位必须为正整数`
  - `源池与目标池不能相同`

#### B3 存储与网络 `/compute/storage`（权限：算力中心）
- **看什么**：存储容量趋势（近 30 日）、分类容量、算力网络平面负载与明细、存储运营自动化等级、数据迁移支持（服务期满）。
- **能做什么**：只读。

#### B4 例外监控与阻断 `/compute/exceptions`（权限：算力中心）——**本页是重点**
- **用途**：发现「不该有的接入 / 不该有的调用 / 未接管到位 / 资源吃紧 / 配额越界 / 目录不一致」，切断它，并把整改闭环跑完。
- **看什么**：例外台账、例外分布、整改闭环台账、值班表与派单时限、后台监控设置、检测数据源、算力池水位、监控规则（阈值与「切什么 / 不切什么」写死在页面上）、处置与整改记录。
- **能做什么**（每一步都生成工单、都留痕）：
  1. 「立即扫描一轮」/ 后台轮扫（默认 20 秒/轮，可「停止轮扫（只手动扫描）」、可改扫描间隔）。
  2. 选中一条例外 → 「分析」看归因链（来源、证据、受影响对象）。
  3. 「阻断接入」或「按范围阻断」：范围可选 **全通道 / 采集项 / 时段 / 来源 IP**。
  4. 「资源侧缓解（不是阻断：动资源，走变更窗口）」：回收 / 抢占 / 回滚，状态与阻断分开（已阻断 / 已缓解 / 已放行）。
  5. 「标记放行（人工放行，留痕，不阻断）」。
  6. 整改闭环：**接单 → 记整改进展 → 提交复核 → 复核通过 / 复核退回 → 关闭**；关闭后才允许「提交恢复工单」。
  7. 「解除部分阻断」、「清空选择」、「清空处置与整改记录」。
  8. 检测数据源面板：把「网段流量探针 / 设备 Syslog·SNMP / CMDB 台账比对」逐条接入或断开。
- **会被拒（有校验，不是想停什么就停什么）**：
  - `来源 IP 写法不对（例：10.42.7.18 或 10.42.7.0/24）`
  - `时段写法不对（例：02:00-06:00）`
  - `「X」阻断须写明要停的对象（例：采集项名称 / 02:00-06:00 / 10.42.7.18）`
  - `该例外没有对应的接入配置，无法做接入阻断` / `该例外没有对应的纳管对象，无法切断调用入口`
  - `先接单再提交复核`、`整改进展要写清做了什么（不少于 6 字）`、`提交复核要写整改结论与依据（不少于 6 字）`、`复核结论要写清依据（不少于 6 字）`、`放行必须写明理由（不少于 6 字）`、`整改单已关闭，如需变更请重开例外监控处置`
- **注意**：阻断只切断**接入来源**（通道 / 凭证 / 应用入口 / 目录入口），算力池、卡位、模型副本、业务服务照常；部分阻断时通道仍启用，只切该来源。

#### B5 算力卡监控（昇腾） `/compute/cards`（权限：算力中心）
- 本页底部另有一张 **「实连 GPU（平台监控探针拉取）」** 表：那是数据服务自己拉到的真实卡指标（利用率 / 显存 / 温度 / 功耗 / 主机 CPU 与内存），
  与上面 64 张卡的**平台推导演示口径**分开显示，页面上写明了哪张表是实连、哪张是推导，不要混着看。
- **用途**：卡位级监控，回答「哪张卡在忙、哪张卡过热、哪张卡掉线」。
- **看什么**：卡位热力网格（8 节点 × 8 卡 = 64 张卡）、卡明细台账（利用率 / HBM / 温度 / 功耗 / ECC / 承载服务）、卡级告警、池对照（卡表 vs 池化分配）、数据来源与接口清单。

- **卡级告警判据**：利用率 > 92% · 温度 ≥ 85℃ · HBM > 95% · 掉卡 / 隔离 · ECC 错误偏高。
- **注意**：**物理 64 卡、池化 46 卡、登记 88 卡**三个口径在同一页对照，现场被问卡数不一致就在这页解释；不可采字段显示「不可采集」，不会推算。

### C. 模型中心

#### C1 模型部署与发布 `/model/deploy`（权限：推理网关）——**新增，选型重点**
- **用途**：把「要上一个模型」变成一张可审批、可下发、可验收的工单。**平台不发容器指令**。
- **流程与按钮**：
  1. 「部署申请表单」填：模型、副本数、每副本卡位、版本、灰度比例、目标节点、镜像 → 「提交部署工单」。
  2. 工单进「部署工单看板」：状态 **待审批** → 管理员「通过」（或填理由「驳回工单」）。
  3. 审批通过后状态停在 **已审批待执行** → 点「下发容器平台」→ 状态变 **已下发·待回执**（此时**卡位不占用、副本不变**）。
  4. 回执来源两种：
     - **自动**：采集层从容器平台取回，出现在「容器平台执行回执（采集层取回）」栏 → 点「按这条回执生效 / 记失败」。
     - **手工**：在看板里填「执行说明（回执必填）」+「实例清单」+ 结果 → 「回填回执」。
  5. 成功回执 → 才生效（「生效对照」里模型多一条、共享池空闲 10 → 6 卡）；失败回执 → 工单 **已驳回**，卡位一个不占。
  6. 可「回滚」→ 卡位归还、模型条目退回。
- **会被拒（都是故意的校验，演示时可以现场踩）**：
  - `要写明部署哪个模型（模型简称或新模型名称）`
  - `要写明目标节点（例：AI-Infer-03 / AI-Infer-04）—— 部署动作由容器平台在这些节点执行，平台只发单与验收`
  - `要写明镜像与版本（例：mindie:2.1.qwen3），执行回执要能对上镜像`
  - `单条部署工单的副本数要在 1–8 之间（更大的发布拆成多条工单，便于逐条回滚）`
  - `灰度比例要在 1–100 之间（灰度发布要写清放量比例）`；版本不在该模型的版本清单里也被拒
  - 容量类：目标池空闲卡位不足、执行后池利用率将超过 92%
  - `回执要写执行结果说明（不少于 6 字），台账与审计要看`
  - `只有模型部署类工单需要下发外部执行并等回执`；未下发直接执行会被门禁挡住
- **注意**：看板里 30 分钟没回执会标「回执超时」；采集层取回但工单号对不上的回执会显示「工单不存在」——选型阶段要定「工单号原样回传」。

- **看什么**：通知列表、来源分布、渠道路由规则。
- **能做什么**：标已读、「清空通知」。
- **注意**：事件（限流、被抢占、吊销、策略驳回、派单、升级）会自动生成通知；演示派单时这里能看到。

#### E5 外部对接清单 `/ops/integrations`（权限：外部对接）——**接真实系统的入口**
- **看什么**：接入配置台账（**28 条**：22 系统类 + 6 资源类）、新增接入配置、商定状态与卡点（谈判用）、中断后的真实影响（可现场演示）、配置字段说明、配置导入导出、「两项配置会直接改变平台能力」。
- **能做什么**：选一条配置点「配置」编辑 → 「保存配置（版本 +1）」；「探活 / 试采」；「真实接口」/「虚拟模拟」切换；启用 / 停用通道、「恢复通道」、「恢复默认配置」、「导入这份配置」；「去资源调配工作台提交一笔超出空闲的扩容」验证新增资源真的可用。
- **会被拒 / 卡点**：外部资源类必须给额度或单价（`外部资源必须给出配额或计费口径（额度为 0 无法接入）`）、名称或协议不合规被拒、`通道已停用，探活不执行`、`未找到该接入配置`。
- **注意**：这里改的是**配置**，不改代码；「中断后的真实影响」面板演示某系统断了之后哪些纳管数据立刻取不到。

#### E6 申请与审批台 `/ops/apply`（权限：资源调配；审批要「审批」）——**新增**
- **用途**：普通用户与管理员共用的一页：业务侧申请、管理侧审批，全部走工单。
- **能做什么**：
  - 「提交 Key 申请」（用途 / RPM / TPM / 期限 / 理由）；「演示：提交一个超上限的申请」看拒绝
  - 「提交训练算例申请」（名称 / 用途 / 框架 / 数据密级 / 卡数 / 时长）；「演示：申请 12 卡（超单申请上限）」看拒绝
  - 「我的申请」看状态；管理员在「审批台」通过或驳回（**驳回必须写理由**）
  - 「待执行与已生效」看执行结果；「训练算例台账」看占卡在跑；「归还卡位」（`train_release` 工单）
- **会被拒**：
  - `个人密钥配额上限 120 RPM`
  - `单个训练算例 1–8 卡；更大的任务拆成多笔申请，便于逐笔回收`
  - `训练时长 1–72 小时；超长期占用要单独排期并走窗口审批`
  - `要写任务名称与用途，台账与成本归集要用`、`要写训练框架（例：MindForm / MindIE），镜像与环境要能对上`、`要写训练数据密级（内部 / 敏感 / 已脱敏），密级门禁与网络平面要核验`
  - 卡数超过训练池当前空闲
- **注意**：申请与审批是**两套权限**——用户 D只能提交，看不到审批台；训练算例执行后池利用率 50% → 75%，归还后回到 50%。

#### E7 台账与审计（查库） `/ops/records`（权限：审计日志）——**新增（v2.3）**

- 四个页签：**工单台账 / 运行事件 / 写入审计 / 数据库概览**。
- 数字不是从页面内存里凑的：每次查询都调数据服务 `/api/orders`、`/api/events`、`/api/audit`、`/api/tables`，
  **服务端过滤与分页**；面板上直接写着本次请求的 URL，可以当场在浏览器里打开同一个地址对照。
- 工单按状态 / 类型 / 关键词检索；事件按级别与关键词检索；审计按账号与动作检索；每页 20 / 50 / 100 条翻页。
- 「导出 CSV（服务端生成）」下载的是带 UTF-8 BOM 的 CSV（`/api/csv?resource=orders`），内容与界面表格同源。
- 数据库概览给出各表行数与最近变更时间，以及库文件位置与版本（`/api/health`、`/api/tables`）。
- 运行事件是**长期留存**：界面上只留最近 80 条，库里按「时间 + 内容」去重累积，翻页能看到更早的事件。
- 会被拒：业务用户账号查审计、导出审计都会返回 403（没有「审计日志」查看权 / 没有「报表导出」权），
  页面上直接显示数据服务给的原因，不用猜。

---

#### E8 配置中心（来源与派单） `/ops/settings`（权限：资源调配可见；改配置要「权限矩阵」操作权）
- **看什么**：四个来源开关（身份来源 / 审批来源 / 通知渠道 / 排班来源）+ 处置指令确认超时；每个开关旁边写清「现在是什么状态、等什么材料」。
- **能做什么**：
  - 切换身份来源（`local / cas / oauth2 / ldap`）。适配器没配置好时选中会明确报错，不会静默退回内建模式。
  - 影子同步：粘贴外部账号清单（每行 `外部账号 | 姓名 | 角色`）→ 执行后返回「共几条 / 可对应几条 / 待绑定几条」，下面是账号映射表；重复执行不会产生重复行。
  - 排班与派单：改每个岗位的当班人 / 内线 / 上级 / 范围，改每类例外的派单岗位与超时升级岗位，可新增岗位。改完立即影响「例外监控与阻断」的自动派单与升级。
- **口径写死在页面上**：先内建独立运行 → 影子同步 → 双写核对（连续对齐 ≥10 个工作日、差异清零）→ 改一个配置项切主源；业务代码与接口契约不变。

#### E9 处置指令台 `/ops/commands`（权限：安全事件查看；下发要「处置下发」，紧急下发要「紧急处置」）
- **能做什么**：选目标设备类型 + 指令动作 + 目标 → ① `先做 dry-run 预检`（列出影响面清单与预检项，不产生任何外部调用）→ ② `看过影响面，确认下发`（没做预检或没二次确认，服务端直接 400）。
- 已下发的指令可「模拟设备确认」「模拟失败」「回滚」（回滚生成反向指令，原指令标「已回滚」）。
- **超时与兜底**：超过配置里的分钟数（默认 30）没确认，指令自动转「待人工兜底」并生成兜底工单；下发失败同样生成。兜底工单可「人工接管」「关闭」。
- **诚实说明**：本期不接真实设备，「模拟确认 / 模拟失败」是演示用的；影响面清单由平台台账推导，不是设备侧真实数据（页面上有这句话）。

#### E10 申请与审批台的「审批来源与外部回写」面板
- 审批来源是配置项：`local` = 本页审批台；`external` = 外部审批系统，本系统登记「外部单据号 + 期望回写时间」并跟踪。
- 外部回写按「工单 + 外部单据号 + 决定」幂等：同一单据号重复回写只生效一次，界面提示「这条回写之前已生效，未重复计算」。
- 超时未回写：台账标「超时」+ 生成人工兜底工单 + 允许在平台内人工审批接管，不会因为外部没回话把业务卡死。

## 4. 四条常用流程（照着走就行）

### 4.1 资源不够怎么办（扩容 / 抢占 / 扩租）
1. `/ops/workflow` →「恢复初始演示数据」→ 选场景包「高保集群吃紧与优先抢占」→ 预置。
2. 在「发起调配申请」提一笔共享池扩容 → 看准入预检结论；若被拒（池空闲不足）→ 点「预填一笔超出空闲的扩容」走**外部扩租**（前提：`/ops/integrations` 里那条外部算力通道已启用且额度充足）。
3. 管理员「通过并执行」→ 看资源账本与池利用率变化、成本变化；再点「回滚」看退回。
4. 想演示排队：先在「变更窗口排期」点「结束窗口」→ 提交的工单进 **排队待窗口** → 预约并开启新窗口 → 工单按序开始执行。

### 4.2 上一个新模型（部署到生效）
1. `/model/deploy` → 填表单 →「提交部署工单」（先点「演示：提交一个不合格参数」看校验）。
2. 看板里「通过」→ 点「下发容器平台」→ 状态 **已下发·待回执**（此时生效对照不变）。
3. 等采集层回执出现在「容器平台执行回执（采集层取回）」→「按这条回执生效」；没有接口就现场「回填回执」（执行说明必填）。
4. 看「生效对照」：模型多一条、共享池空闲 10 → 6 卡。再「回滚」恢复。
5. 顺带演示失败回执：工单变 **已驳回 · 执行失败**，一个卡位没占。

### 4.3 发现旁路接入到恢复接入（闭环演示）
1. `/compute/exceptions` →「立即扫描一轮」（或先造一条演示旁路接入）。
2. 选一条 →「分析」看归因 →「阻断接入」或「按范围阻断」（选「来源 IP」写 `10.42.7.18`）。
3. 下方「整改闭环台账」自动多一张单，派给对应值班角色 →「接单」→ 记整改进展 →「提交复核」→ 管理员「复核退回」（依据不足）→ 补记录再提交 →「复核通过」→「关闭」。
4. 关闭后才允许「提交恢复工单」（引擎还会再做一次就绪校验）。
5. 加分项：把接单时限调成立即再扫一轮 → 待接单变 **已升级** 并产生紧急事件；对比「资源侧缓解」与「阻断接入」的差别。

### 4.4 业务用户申请 → 管理员审批
1. 退出登录 → 用**用户 D**登录 → `/ops/apply` →「演示：提交一个超上限的申请」（看 120 RPM 上限）→ 改 60 RPM 提交成功；「提交训练算例申请」4 卡提交。
2. 换**管理员 A**登录 → `/ops/apply`「审批台」→ 通过 → 「待执行与已生效」看结果 → 训练池利用率 50% → 75%。
3. 在「训练算例台账」点「归还卡位」→ 利用率回到 50%，台账留归还记录。

### 4.5 出报表
1. `/ops/analytics` → 切「按用量占比」↔「按预算科目权重」看同一批数字两种算法。
2. 点地市下钻到区县 → 生成报表 →「数据导出（台账 CSV）」下载。
3. 导出的 CSV 用 Excel / WPS 直接打开即可（导出带 UTF-8 BOM，中文不乱码）。

---

### 4.6 一次处置指令怎么走（不接真实设备的完整流程）
1. `/ops/commands` → 选「旁路接入设备 / 阻断接入通道 / 目标 hp」→ **先做 dry-run 预检**。
2. 看影响面清单（会牵连哪些凭证 / 模型副本 / 纳管对象 / 通道）与预检项，勾选紧急通道需要「紧急处置」权限。
3. **确认下发** → 状态「已下发」，事件流与审计各留一条。
4. 等设备确认：演示里点「模拟设备确认」；不确认超过 30 分钟（配置中心可改）自动转「待人工兜底」。
5. 失败或超时都会生成兜底工单 → 点「人工接管」，处置才算有人接住。
6. 需要撤回：点「回滚」，生成反向指令（`rollback_of` 指向原指令），原指令标「已回滚」。

### 4.7 外部审批不回话时怎么办
1. 配置中心把 `approval-source` 切成 `external` → 在「申请与审批台」给工单登记外部单据号与期望回写时间。
2. 外部回写：`POST /api/approval/callback`（演示里用「人工审批 / 人工驳回」按钮模拟回写，走的就是同一套接口）。
3. 超时未回写：台账标「超时」+ 兜底工单 + 可在平台内人工审批接管。

### 4.8 挂一台真实推理服务并开始监控（平台内置探针，只读）
1. 用**管理员 A**或**运营 B**登录（要「算力中心」操作权）→ `/model/monitor` → 面板「平台内置监控探针」。
2. 填三样：目标显示名、地址（例 `http://10.20.14.21:8081`，要对方服务暴露 `/metrics` 与 `/health`）、
   **取密钥的环境变量名**（例 `MODEL_SVC_API_KEY`；密钥本身要在启动数据服务前 `export` 好，库和前端都不存密钥）。
3. 选**取数口径**：对方 `/metrics` 返回 JSON 就选「JSON 指标」；是 Prometheus 文本（llama-server 加 `--metrics`、vLLM、GPU Exporter）就选「Prometheus 文本」；
   只有 OpenAI 兼容接口（`/v1/models`）就选「只有 OpenAI 兼容接口」。默认 30 秒一轮 → 点「挂上目标并采一轮」。第一轮采不到也会告诉你原因（连不通 / 没密钥 / 指标格式不对）。
4. 勾「主动探测」才会每轮发一个 16 词元的小请求（测真实时延与吞吐）；不勾就完全只读。**只有 OpenAI 兼容口径需要勾它**，否则这一列会写「对方未开放」。
5. 采到之后：本页出现时延与算力侧趋势曲线 + 采样台账；`/compute/cards` 底部出现这台机器的**真实卡指标**（对方不开放时那一行写「对方未开放」，不会填 0）；
   `/ops/records` → 数据库概览能看到 `metric_samples` / `gpu_cards` 行数在长。
6. 口径：探针默认只读（`GET`），不向被监控服务写任何东西；连不通时写一条「取数失败」样本并留审计，
   台账里能看到「从什么时候开始采不到」，不会静默变成空页。关掉探针：启动数据服务前设 `AIOPS_MONITOR=0`。

> 与采集层的分工：**采集层**（`collector/collect.py` → `dist/data/*.json`）负责把外部数据喂给各页面的主表格；
> **内置探针**负责把带时间的采样存进数据库，出趋势、算超阈值、留断连记录。两条路都是只读，互不覆盖。

### 4.9 网络断了会怎样（断连告警，v3.9）

监控目标或采集源连不通（对方重启、网线断了、地址填错、防火墙拦了），系统**不会只在页面里写一行状态**：

1. 每一轮采不到都会留痕：目标显示「取数失败」+ 连续第几轮 + 最近一次错误；采样台账里也多一条「取数中断」记录。
2. 连续采不到达到阈值（默认连续 2 轮）就告警，一次同时落三处：
   - **事件台账**：`【监控断连】… 取数中断：连续 N 轮采不到`（连续 3 轮及以上记「紧急」，否则「重要」）；
   - **通知中心**：标题「某某 取数中断：连续 N 轮采不到」，正文含最近一次错误，并写明「断连期间页面上的指标不再更新，看到的是最后一次成功采到的读数」；
   - **兜底工单**：状态「待接管」，按派单映射派给「资源异常」对应的值班岗位（默认「算力资源值班」），值班员在兜底页签领取。
3. 只告一次不刷屏：后面几轮继续留痕，不再重复发通知。
4. 通了之后自动收尾：状态回「正常」、连续计数清零、通知中心多一条「取数已恢复」（级别「一般」）、兜底工单自动变「已关闭」。
5. 可调：配置中心 → 「资源接入与采集」面板右下角，「断连要告警」开关 + 「连续几轮采不到就告警」（1 / 2 / 3 / 5，默认 2）。
   关掉开关时仍然留痕（状态与连续轮数），只是不发通知、不开兜底工单。
6. 监控页顶部会出现一条橙色提示，列出当前正在告警的目标；目标行的「最近一轮」列写「已告警 · 连续 N 轮采不到」。
7. **没人接管会被追**：兜底工单挂超过 15 分钟（可配 0 / 10 / 15 / 30 / 60，0 = 不自动升级）无人接管 → 工单状态变「已升级」、
   改派给派单映射里「资源异常」的带班角色（默认「值班长」），并追加一条「紧急」通知「某某 无人接管，已升级」。
   值班长也可以随时点「巡检兜底工单」手动追一遍，看到当前待接管清单。
8. **闭环要落到人**：兜底页签（监控页下方「断连兜底工单」表）里，值班员点「我接管」→ 工单状态变「已接管」、归谁写成登录人的名字、审计 `monitor_fallback_take`；
   处置完点「处置完毕 · 关闭」并填原因（不填原因系统不让关）→ 状态「已关闭」、审计 `monitor_fallback_close`。
   如果目标此刻还是采不到，系统会回一句「关闭只是处置登记，不代表它已经通」，避免把工单关掉就等于以为它好了。
9. 通知中心页面顶部新增「真实告警通知（数据服务写进库里的）」面板：这里才是监控断连 / 兜底升级 / 恢复通知的落点（下面的「通知列表」是演示推导的通知，两者不是一回事）。
   未处置的会一直挂着，处置要点「我处置了」并写一句说明（可空）→ 记录是谁、几点、写审计 `monitor_notify_ack`；需要「运营分析」操作权。
10. **只有中断和升级需要你处置**：「取数已恢复」这类通知由系统自动记为已处置（`handled_by` 写「系统自动闭环」），不用你点；面板上的「重新拉取」可以随时按库里的真实状态刷新列表。
11. **值班第一眼看到的地方读的是真实告警**：顶栏铃铛显示「真实告警待处置 N 条」，旁边直接列出最近一条（等级 + 标题 + 时间）；侧栏「通知中心」的红色角标同口径；前端每 20 秒跟库里的状态对齐一次。通知页指标也是真实口径：真实告警待处置 / 紧急待处置 / 已处置（含系统自动闭环）。演示推导出来的通知放在单独的「通知列表（演示推导 · 不是真实采集）」面板里，不与真实告警混列。
12. 界面上点了没反应时先查审计：未知接口（路径写错）、缺少令牌、权限不够都会留记录（`unknown_api` / `denied_csrf` / `denied_monitor_notify_ack`）；库里没有痕迹说明请求没发出去，页面多半是旧版本。
13. 先分清是哪一类问题（决定找谁）：目标行错误写 `Connection refused` = 端口没人监听（服务没起来 / 端口错）；
   写 `timed out` 且 TCP 端口能连上 = 通道通、服务不响应（进程卡死、正在重载模型、请求队列堵死）；
   写 `401 Unauthorized` = 服务活着但密钥不对。处置动作不同，别一上来就当网络问题。

> 还没做（不装已完成）：时延 / 错误率 / 排队深度这类**指标阈值**告警（例如 TTFT > 900 毫秒）目前还写在页面常量里，
> 下一步搬进配置项，跟断连告业务用同一套落点（事件 + 通知 + 兜底工单）。

## 5. 接公司内网真实数据（管理员操作）

**加资源不改成品代码，也不改配置文件**：运营分析 → 配置中心 → 面板「资源接入与采集」。

1. 选资源类型（推理服务 / 算力卡 / 网关 / 路由 / 应用 / 部署台账），填显示名 + 地址 + 取数口径 + 采集间隔 +
   取密钥的环境变量名（配置里只写 `env:变量名` 引用，明文密钥会被直接拒）。
2. 需要特殊指标名（例如 DCGM / NPU Exporter 的指标名、每副本卡数）写在「附加配置」里（JSON 对象），不用改代码。
3. 点「接入这个资源并采一轮」：默认登记即生效并写审计；打开面板右上角「接入要先审批」后，
   会先生成一张 `resource_onboard` 工单，源显示「待审批」，在审批台通过后才生效（驳回则不生效）。
4. 之后所有变更（改地址、改口径、改间隔、停用、删除）都在这个面板做；采集线程在数据服务里，按每个源的间隔自动跑。
5. 采集状态表能看到每个类型「本轮条数 / 最近采集时间 / 错误」；连不通的源会标「取数失败」并保留错误文本。
6. 老配置迁移：面板里点「从采集脚本配置文件导入」，把 `collector/config.json` 一次性搬进系统；搬完之后文件不再被读。

> `npu-smi` 直采（不在卡上装 Exporter 时的兜底）仍只在采集脚本 `collector/collect.py` 里保留 —— 它要在数据服务所在机器上执行命令，
> 不适合由界面触发。卡指标推荐走 NPU Exporter / NVML Exporter 的 Prometheus 端点。

## 6. 术语与状态对照表

### 6.1 工单类型（16 类）
| 类型 | 出现在哪 | 生效后的实际影响 |
|---|---|---|
| 资源池扩容 / 回收 | `/ops/workflow`、`/compute/schedule` | 池卡位变化、利用率变化 |
| 高保优先抢占 | `/compute/schedule`、工作台 | 共享 → 高保转移卡位（仅高保业务可用） |
| 推理副本扩缩 | `/model/monitor`、`/model/gateway` | 模型副本数变化 |
| 路由权重调整 | `/model/gateway` | 渠道分流比例变化 |
| 凭证发放 / 回收吊销 / 配额调整 | `/model/credentials`、`/ops/apply`、`/model/litellm` | Key 可用性与 RPM/TPM 上限 |
| 运行处置动作 | `/app/security`、`/model/security` | 暂停 / 限流 / 隔离 / 禁用（切调用，不动资源） |
| 模型版本回退 / 下线变更 | `/model/assets` | 模型版本与在架状态 |
| 接入通道阻断 / 恢复 | `/compute/exceptions` | 切断或恢复一条接入（可部分阻断） |
| **模型部署与发布** | `/model/deploy` | **等外部执行回执到位才变副本与卡位** |
| **训练算例申请 / 归还** | `/ops/apply` | 训练池占卡与归还 |

### 6.2 工单状态（8 态）
`待审批` → `已审批待执行` →（无窗口时）`排队待窗口` →（部署类）`已下发·待回执` → `执行中` → `已闭环`；中途可 `已驳回` 或执行后 `已回滚`。

### 6.3 例外六类（判据写在页面上，可确认）
| 类型 | 判据 | 切断什么 | 明确不切断什么 |
|---|---|---|---|
| 旁路接入 | 前置条件完成数 = 0 或出现游离接入 | 这条接入通道（停采集与调用） | 它对应的算力池与模型 |
| 旁路调用 | 已暂停 / 隔离 / 禁用对象仍有调用量 | 目录入口 + 吊销其凭证 | 对象所在资源不下线 |
| 接管缺口 | 算力类登记对象深度 < L4 | 该对象对外调用入口 | 不回收卡位、不停资源 |
| 资源异常 | 利用率 ≥ 92% · 错误率 ≥ 4% · 扩租超额 · 容器重启 | 限流或切断超额调用来源 | 回收 / 抢占 / 扩容属资源侧缓解，走变更窗口 |
| 配额越界 | 凭证 RPM 超上限 · 外部 Token 超配额 | 吊销或限流该凭证，必要时阻断外部渠道 | 不回收本地卡位 |
| 目录不一致 | 技术目录与使用目录在架状态不一致 | 双侧同步摘除目录入口 | 不摘除服务与算力本身 |

### 6.4 接管深度
| 深度 | 要达到什么 | 能做什么 |
|---|---|---|
| L1 可见 | 登记在册 | 只统计 |
| L2 可度量 | 接入通道启用且健康 | 能采数据 |
| L3 可处置 | 接口状态「已定」 | 能下处置动作 |
| L4 可调度 | 接口已定 + 执行回执类前置完成 | 进统一调度与容量编排 |

### 6.5 接入配置（28 条）
类别 8 种：已建子系统、安全设备、基础服务、外部算力资源、外部模型渠道、外部存储与备份、外部数据源、监控与日志外送。
每条字段：名称、类别、方向、模式（虚拟模拟 / 真实接口）、协议、地址、鉴权、采集项、采集间隔、超时、重试、降级策略、启用状态、商定状态、归口与联系人、健康、卡点说明、前置条件与完成项、额度与单价、版本号、变更历史。

| 菜单少了几项、某页打不开 | 当前账号没有该权限点 | 换管理员账号，或在 `/app/accounts` 权限矩阵打开对应格（演示完「恢复默认矩阵」） |
| 数字不动 | 自动采样关了 | `/ops/workflow` 开自动采样或点「采样一次」 |
| 工单一直「排队待窗口」 | 没有开放中的变更窗口 | `/ops/workflow` 排期里开启窗口，或先结束当前再预约；紧急处置类不占窗口 |
| 部署工单一直「已下发·待回执」并标红 | 没有执行回执（超 30 分钟标「回执超时」） | 接采集层取回执，或现场「回填回执」（说明必填、≥6 字） |
| 页面顶部写「取数失败」 | 采集脚本该来源本轮没取到 | 看 `manifest.json` 里该文件的原因（地址 / 鉴权 / 网段 / 未配置）；页面会自动回落平台推导，**不要手工补数** |
| 演示数字乱了、对不上 | 之前做了多轮操作 | `/ops/workflow`「恢复初始演示数据」（清库再写初始值）；仍不对就停服务、删 `server/data/aiops.db` 后重启 |
| 导出的 CSV 中文乱码 | 用了不认 BOM 的老工具 | 用 Excel / WPS 直接打开（导出已带 UTF-8 BOM）；或用「数据 → 从文本导入」选 UTF-8 |
| 手机上宽表格看不全 | 明细表宽度较大（为投屏设计） | 横向滑动；投屏与讲解建议用电脑 |
| 双击 `start.bat` 窗口一闪而过 | Python 指向了微软商店占位程序 | 地址栏 `cmd` 回车，执行 `powershell -ExecutionPolicy Bypass -File start.ps1` |
| 打开页面就回到登录页 / 提示未登录 | 会话过期（8 小时无操作）或浏览器 Cookie 被清 | 重新登录（演示口令见 §1.2）；会话是 HttpOnly Cookie，前端改不了 |
| 保存时出现「角色「××」没有「××」的写入权限」 | 数据服务的权限判定拦下了（不是前端问题） | 换有该权限点的账号，或在 `/app/accounts` 权限矩阵打开该权限点（改矩阵本身需要「权限矩阵」权限） |
| 输错几次口令后被拒绝登录 | 同一账号 5 分钟内失败 5 次触发限流 | 等 5 分钟或换账号；每次成功与失败都在 `login_log` 里，`/api/csv?resource=audit` 可查登录动作 |
| 右上角显示「数据服务未连接 · 本次不保存」 | 数据服务没起，或访问的是纯静态页面 | 用 `start.bat` / `start.sh` / `python server/server.py` 启动；确认地址是 `http://127.0.0.1:<端口>/`；界面仍可操作但**不会保存**，演示前务必先解决 |
| 右上角显示「写入失败 · 重试中」 | 数据库文件或数据服务被占用、磁盘不可写 | 看服务窗口报错；换可写目录或换端口重启；恢复后会自动补写，不用手工重做 |
| 换了一台电脑数据不见了 | 数据库文件没带走 | 拷贝 `server/data/aiops.db`（含 `-wal` / `-shm`）到新机器同路径；或用 `/api/export` 导出后重建 |
| 想看后台到底存了什么 | 界面不直接展示表 | 浏览器打开 `/api/health`、`/api/orders`、`/api/audit`、`/api/export`；表结构见 `server/schema.sql` |

## 9. 使用纪律（演示与选型阶段务必照做）

1. **数字都是虚拟的**，页面左下角常驻提示；讲的时候直说，不回避。数字之间的**推导关系、门禁、校验、留痕**是真的。
2. **不现场承诺**下列事项，统一回答「待商定 / 待客户方提供」：真实统一身份认证与零信任、6 类安全设备的真实联动、商用密码改造与密评、SLA / 双活、子系统自身的开发能力（编排、向量化、插件分发、Skill 仓库、真实训练与评测）。
3. 每个场景前先「恢复初始演示数据」；改过权限矩阵要恢复默认。
4. 讲数据来源时，明确当前是「采集层」还是「平台推导」，不要把推导值说成实测值。
5. 平台侧动作边界要讲清：**平台发单与验收，外部执行与回执**；卡与推理服务的指标来自采集层，不可采字段显示「不可采集」。
